# ADR 005: Equal Chroma for the Palette

## Status

Accepted

## Context

ADR 003 で6色の OKLCH 明度を0.80に揃えたが、彩度は元のパレットの値を引き継いでいた。OKLCH 彩度は0.079（黄・シアン）から0.139（マゼンタ）まで約1.8倍の開きがあり、マゼンタと緑が鮮やかに、黄とシアンが淡く見えた。

| 名前 | HEX | OKLCH C |
|---|---|---|
| Red | #F6A5A5 | 0.096 |
| Yellow | #C2C286 | 0.079 |
| Green | #86D486 | 0.133 |
| Cyan | #7ECECE | 0.079 |
| Blue | #B5B5FF | 0.104 |
| Magenta | #ED9DED | 0.139 |

彩度を揃えるには sRGB の色域が制約になる。明度0.80で各色相が取れる最大の彩度は、青が0.104で最も小さく、緑は0.273まで取れる。

## Decision

6色の OKLCH 彩度を0.104に揃える。これは明度0.80で6色すべてが sRGB に収まる最大の共通値である。青がその上限を決める。

色相（HSL の6等分、ADR 001・004）と明度0.80（ADR 003）は変えない。各色は、HSL 色相を正確に満たす sRGB の色のうち、OKLCH 明度が0.80±0.002で彩度が0.104に最も近いものを選ぶ。

採用する値は次のとおり。

| 名前 | HEX | OKLCH L | OKLCH C |
|---|---|---|---|
| Red | #F9A2A2 | 0.80 | 0.104 |
| Yellow | #C3C372 | 0.80 | 0.104 |
| Green | #94D094 | 0.80 | 0.104 |
| Cyan | #5FD3D3 | 0.80 | 0.105 |
| Blue | #B5B5FF | 0.80 | 0.104 |
| Magenta | #E1A6E1 | 0.80 | 0.104 |

## Alternatives

### Alternative 1: 彩度を元の値のまま残す

ADR 003 の状態を維持する。変更がないのが長所である。短所は、色によって鮮やかさが1.8倍違い、マゼンタと緑だけが目立つことである。選ばなかった。

### Alternative 2: 彩度の目標を平均（0.105）付近より高くする

0.12や0.13に揃える。全体が鮮やかになる。短所は、青と赤が sRGB に収まらず、その2色だけ彩度を落とすか明度を変える必要があることである。6色の統一を優先し、選ばなかった。

### Alternative 3: 明度を下げて彩度の上限を広げる

明度を0.70などに下げると、青もより高い彩度を取れる。短所は、全体が暗くなり淡い色調という印象が変わることである。ADR 003 の明度0.80を優先し、選ばなかった。

## Confidence Level

高い。明度と彩度は計算で求めた値で、6色が明度0.80±0.002、彩度0.104±0.001に収まることを確認した。

次の場合は見直す。
- 明度の目標値（ADR 003）を変えたとき。取れる彩度の上限が変わる。
- sRGB より広い色域で表示するとき。青の上限が上がる。
- 彩度0.104が実際のサイトで物足りないと分かったとき。Alternative 3 を検討する。

## Consequences

良い結果
- 6色が同じ明るさで同じ鮮やかさに見える。どの色のタグも同じ程度に目立つ。
- 黄とシアンが今までより鮮やかになる。

悪い結果
- 同じタグから生成されるアイコンと下線の色が変わる。
- マゼンタと緑は今までより淡くなる。
- 彩度の上限を青が決めるので、他の色相が持てる鮮やかさを使い切れない。

中立的な結果
- `tests/golden.rs` の期待値を新しい色に更新した。下線の形は変わっていない。
- 色の調整は `cargo run --example swatches > swatches.html` で確認できる。
