# ADR 002: Darker Color for the Dots Pattern

## Status

Accepted

## Context

ハッチパターンは、パレットの色で線や点を描き、隙間は透明にする。パターンによって色が塗られる面積の割合が異なる。Dots は8pxのタイルに4px角の点を1つ置くので、塗られる面積はタイルの25%にすぎない。線のパターンは30%から50%、Checker は50%である。

パレットは淡い色で揃えている（ADR 001）。塗られる面積が小さい Dots では、この淡い色が白い背景に溶け込み、全体がさらに薄く見える。色見本（`swatches.html`）で6色を並べたところ、Dots の列だけ他の列より明らかに見にくかった。

点を大きくして面積を増やす調整は先に行った（2px角から4px角へ）。それでもまだ見にくかった。これ以上点を大きくすると、PolkaDots や Checker との区別がつきにくくなる。

## Decision

Dots パターンのときだけ、色の明度を0.8倍にする。各パターンは `HatchPatternType::brightness` で自分の明度係数を返し、Dots は0.8、他は1.0である。`to_svg_pattern` はパターンの種類で分岐せず、この係数を `Color::change_brightness` に一律に渡してから描く。係数1.0は色を変えない。

例えば Red は #F9A2A2 から #F45454 になる（ADR 005 の値）。色相と彩度は変えないので、どのパレット色かは見分けられる。

パレットの定義（`src/colors.rs`）は変えない。調整はパターンを描く側に閉じ込め、Dots 以外のパターンや塗りつぶし、下線には影響を与えない。

## Alternatives

### Alternative 1: 点をさらに大きくする

点を4px角より大きくして、塗られる面積を増やす。色の処理に手を入れずに済むのが長所である。短所は、点が大きくなるほど PolkaDots や Checker に似てくることである。パターンの区別を優先し、選ばなかった。

### Alternative 2: パレット全体の明度を下げる

6色の明度を77%から下げ、すべてのパターンを濃くする。Dots 専用の処理が要らないのが長所である。短所は、Fill や太い線のパターンまで濃くなり、淡い色調という全体の印象が変わることである。Dots 以外は現状で十分見えているため、選ばなかった。

### Alternative 3: Dots を廃止する

見にくいパターンをなくし、11種類にする。最も単純な解決である。短所は、パターンの種類が減り、タグから生成されるアイコンの多様性が下がることである。また、Dots を選んでいたタグはすべて別のパターンに変わる。多様性を優先し、選ばなかった。

## Confidence Level

中程度。係数0.8は色見本を目視して決めた値で、根拠は見た目だけである。6色すべてで Dots の列が他の列と同じ程度に見えることは確認した。

次の場合は見直す。
- 他のパターンでも同じように見にくいものが見つかったとき。パターンごとに係数を持つ仕組みに広げる。
- パレットの明度を変えたとき（ADR 003 の見直し）。0.8という係数の前提が変わる。
- ダークモードなど、暗い背景で使うとき。暗くする方向の調整が逆効果になる。

## Consequences

良い結果
- Dots が白い背景で他のパターンと同じ程度に見えるようになる。
- パレットと他のパターンは変わらないので、影響は Dots を使うアイコンに限られる。

悪い結果
- Dots のアイコンだけ色が濃くなる。同じタグ色でも、パターンによって色味が違って見える。
- パターンごとに色を変える前例ができる。今後、他のパターンにも調整が増えると、`to_svg_pattern` が複雑になる。

中立的な結果
- `IconBuilder::background_colors` が返す色はパレットの色のままで、Dots の濃い色ではない。下線はパレットの色を使うので、Dots のアイコンと下線の色味が少し異なる。
- 調整の効果は `cargo run --example swatches > swatches.html` で確認できる。
