# ADR 001: Six Evenly Spaced Hues for the Palette

## Status

Accepted

## Context

パレットは6色で、タグのハッシュから選ばれる。元のC#版 picturesque-tags は、Adobe Color のトライアド規則で選んだ2組の色を使っていたが、厳密なトライアドではなく、わたしが感覚的に調整したものだった。実際の色相を計算すると120°間隔になっていなかった。triad01 の間隔は78°・137°・145°、triad02 の間隔は138°・147°・75° だった。

6色を1つの色相環に並べると、間隔は34°から110°までばらついていた。特に緑（92°）と水色（193°）の間が大きく空き、黄（55°）・緑（92°）と、青（230°）・ピンク（340°）が近かった。近い色相の色は、ハッチパターン越しに見ると区別しにくい。また、黄（#EBE49A）は緑成分が多く、人間の目には明るすぎて視認しづらかった。

一方で、彩度（67%）と明度（77%）は6色とも揃っていた。この統一感は保ちたい。

また、色の名前が色相と合わなくなった。Orange と名付けられた色は、調整後に色相0°の赤になった。Pink と名付けられた色は色相300°で、ピンクよりマゼンタに近い。色相環の6等分（赤・黄・緑・シアン・青・マゼンタ）に合わせた名前のほうが、全体を眺めたときに整合する。

## Decision

パレットを、色相環を60°ずつ等分した6色に変更する。基準を赤の0°に置き、0°・60°・120°・180°・240°・300°を採用する。これは互いに60°ずれた2つの厳密なトライアド（0°・120°・240°と60°・180°・300°）でもある。

彩度67%と明度77%は元のパレットから引き継ぎ、6色で揃える。

黄だけは例外として、60°ではなく46°に置く。元の色は緑成分が多いため、人間の目には明るく見える。オレンジ寄りにしたほうが視認性が高まるため、調整した。

色の名前は色相環の6等分に合わせ、Red・Yellow・Green・Cyan・Blue・Magenta とする。Orange を Red に、Pink を Magenta に改名する。

採用する値は次のとおり。

| 名前 | HEX | 色相 |
|---|---|---|
| Red | #EB9B9B | 0° |
| Yellow | #EBD89B | 46° |
| Green | #9BEB9B | 120° |
| Cyan | #9BEBEB | 180° |
| Blue | #9B9BEB | 240° |
| Magenta | #EB9BEB | 300° |

## Alternatives

### Alternative 1: 元のパレットを維持する

元の6色をそのまま使う。既存のアイコンや下線の色が変わらないのが長所である。短所は、色相の間隔がばらつき、黄と緑、青とピンクが区別しにくいことである。黄が明るすぎて視認しづらい問題も残る。色の区別のしやすさを優先し、選ばなかった。

### Alternative 2: 2組をそれぞれ厳密なトライアドにする

元の赤（14°）と黄（55°）を基準に、各組を120°間隔に直す。14°・134°・254°と55°・175°・295°になる。元の色に近く、変化が小さいのが長所である。短所は、2組の間のずれが41°と79°で不均等なままで、6色としては等間隔にならないことである。6色全体の区別のしやすさを優先し、選ばなかった。

## Confidence Level

高い。色相を等間隔にすると色の区別がつきやすくなることは、色見本（`swatches.html`）で6色×12パターンの全組み合わせを確認した。彩度と明度は元のパレットから変えていないので、全体の印象は保たれる。

黄の46°という値は目視で決めた。表示環境や背景色が変われば、見え方は変わりうる。

次の場合は見直す。
- 実際のサイトで、特定の色の組み合わせが区別しにくいと分かったとき。
- 色の数を増減するとき。等間隔の前提が変わる。
- ダークモードなど、明るい背景以外で使うとき。明度77%は明るい背景を前提にしている。

## Consequences

良い結果
- 6色が色相環で等間隔に近くなり、ハッチパターン越しでも区別しやすくなる。
- 黄が暗くなり、視認性が上がる。
- 色の名前が色相と一致し、コードを読むときに迷わない。

悪い結果
- 同じタグから生成されるアイコンと下線の色が変わる。既存の利用者が見た目の変化に気づく。
- `ColorName::Orange` と `ColorName::Pink` がなくなる。この enum を直接使うコードはコンパイルできなくなる。破壊的変更として扱う。
- 黄だけ等間隔から外れている。等間隔という説明に例外がつく。

中立的な結果
- `tests/golden.rs` の期待値を新しい色に更新した。下線の形は変わっていない。
- 色の調整は `cargo run --example swatches > swatches.html` で確認できる。今後の調整もこの見本を使う。
