# ADR 004: Yellow Back to 60 Degrees

## Status

Accepted。黄の具体的な値は ADR 005 で #C3C372 に更新した。色相60°の決定は有効である。

## Context

ADR 001 は6色を HSL の色相環で60°間隔に並べたが、黄だけは例外として60°ではなく46°に置いた。60°の黄は緑成分が多く、人間の目には明るすぎて白い背景で見づらかったためである。

ADR 003 で6色の OKLCH 明度を0.80に揃えた。黄が明るすぎるという問題は、明度を揃えることで解消した。46°という例外を置いた理由がなくなった。

一方で、例外が残ると「6色は60°間隔のヘクサード」という説明に但し書きがつく。黄がオレンジに寄っているため、赤（0°）との間隔が46°と狭く、緑（120°）との間隔が74°と広い。

## Decision

黄を HSL 色相60°に戻す。6色は0°・60°・120°・180°・240°・300°の正確なヘクサード（色相環の6等分）になる。

黄の値は、HSL 色相60°（R=G>B）を満たす sRGB の色のうち、OKLCH 明度が0.80で、彩度が ADR 003 の黄（0.081）に最も近いものを選ぶ。採用する値は #C2C286（OKLCH L=0.800、C=0.079、h=108°）である。

他の5色は ADR 003 のまま変えない。

## Alternatives

### Alternative 1: 46°のまま残す

ADR 001 の値を維持する。変更がないのが長所である。短所は、例外の理由がなくなったのに例外だけが残ることである。選ばなかった。

### Alternative 2: OKLCH の色相で120°間隔にする

HSL ではなく OKLCH の色相環でヘクサードを組む。知覚的に等間隔になる。短所は、6色すべてが変わり、赤・緑・青といった名前と色の対応が崩れることである。HSL のヘクサードという ADR 001 の枠組みを保つため、選ばなかった。

## Confidence Level

高い。明度は計算で揃えてあり、黄が明るすぎる問題は再発しない。60°の黄が緑に近く見えるかどうかは、色見本（`swatches.html`）で緑（120°）と並べて区別できることを確認する。

次の場合は見直す。
- 実際のサイトで黄と緑が区別しにくいと分かったとき。
- ADR 003 の明度の目標値を変えたとき。黄の値を再計算する。

## Consequences

良い結果
- 6色が正確なヘクサードになり、説明に例外がなくなる。
- 赤と黄、黄と緑の間隔が等しくなる。

悪い結果
- 黄のタグを使うアイコンと下線の色が変わる。

中立的な結果
- `tests/golden.rs` の期待値を新しい黄に更新した。下線の形は変わっていない。
