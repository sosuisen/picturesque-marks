# ADR 003: Equal Perceptual Lightness for the Palette

## Status

Accepted。彩度を元の値のまま残す決定は ADR 005 で置き換えた。明度0.80の決定は有効である。

## Context

ADR 001 のパレットは、6色の HSL 明度を77%、彩度を67%に揃えていた。しかし HSL の明度は人間の目が感じる明るさとは一致しない。同じ HSL 明度でも、黄・緑・シアンは明るく見え、赤・青は暗く見える。

知覚的に均等な色空間 OKLCH で6色の明度（L）を測ると、0.72から0.89までばらついていた。

| 名前 | HEX | OKLCH L |
|---|---|---|
| Red | #EB9B9B | 0.77 |
| Yellow | #EBD89B | 0.88 |
| Green | #9BEB9B | 0.87 |
| Cyan | #9BEBEB | 0.89 |
| Blue | #9B9BEB | 0.72 |
| Magenta | #EB9BEB | 0.80 |

このばらつきのせいで、白い背景では黄・緑・シアンが薄く見え、青は他より濃く見えた。ADR 001 で黄を46°に寄せた調整も、ADR 002 で Dots を暗くした調整も、この明るさの差に起因する問題への対処だった。

## Decision

6色の OKLCH 明度を0.80に揃える。0.80は元の6色の平均（0.82）に近い丸い値である。

色相は変えない。各色の OKLCH 色相と彩度を元のパレットから引き継ぎ、明度だけを0.80に置き換える。sRGB に丸めたあと、HSL の色相が ADR 001 の値から1°ずれた緑と青は、正確な120°と240°になるよう1段階だけ調整する。

青だけは例外として、彩度を0.115から0.104に下げる。明度0.80の青は、元の彩度では sRGB の色域に入らないためである。色相と明度を優先し、色域に入る最大の彩度を使う。

採用する値は次のとおり。

| 名前 | HEX | OKLCH L | OKLCH C | OKLCH h |
|---|---|---|---|---|
| Red | #F6A5A5 | 0.80 | 0.096 | 19° |
| Yellow | #D0BD81 | 0.80 | 0.081 | 93° |
| Green | #86D486 | 0.80 | 0.133 | 144° |
| Cyan | #7ECECE | 0.80 | 0.079 | 196° |
| Blue | #B5B5FF | 0.80 | 0.104 | 284° |
| Magenta | #ED9DED | 0.80 | 0.139 | 327° |

ADR 001 の「彩度67%と明度77%を6色で揃える」という決定は、この ADR で置き換える。色相60°間隔の決定と黄の46°は変えない。黄の46°はこのあと ADR 004 で60°に戻した。黄の値は ADR 004 を参照すること。

## Alternatives

### Alternative 1: HSL の明度だけを色ごとに変える

HSL の色相と彩度67%を保ち、HSL の明度だけを色ごとに調整して OKLCH 明度を0.80にする。ADR 001 の彩度の統一を保てるのが長所である。短所は、暗くする色の HSL 彩度が相対的に強く見えることである。シアンは #35D6D7、黄は #DCBA4E のような鮮やかな色になり、淡い色調という全体の印象が崩れる。選ばなかった。

### Alternative 2: 明度の目標を元の赤に合わせる（0.77）

赤を変えず、他の5色を赤に合わせる。変化する色が5色で済むのが長所である。短所は、青を明るくする量が少なく済む一方で、黄・緑・シアンの変化が大きくなることである。また0.77は青以外のどの色の中間でもない。平均に近い0.80を選んだ。

### Alternative 3: 6色の彩度も揃える

明度に加えて OKLCH 彩度も同じ値にする。最も統一感が出る。短所は、黄とシアンの彩度（0.08）に揃えると緑とマゼンタが灰色に近づき、緑の彩度（0.13）に揃えると黄と青が色域から外れることである。彩度は元の値を保つことにした。

## Confidence Level

高い。OKLCH の明度は計算で求めた値で、目視による調整ではない。6色の明度が0.80±0.002に収まることを確認した。

青の彩度は色域の制約で決まった。sRGB 以外の色域で表示する場面では、見直す余地がある。

次の場合は見直す。
- 明度0.80が実際のサイトで薄すぎる、または濃すぎると分かったとき。目標値を変えて6色を再計算する。
- ダークモードなど、暗い背景で使うとき。明度0.80は明るい背景を前提にしている。
- ADR 002 の Dots の係数0.8が合わなくなったとき。6色の明るさが揃ったので、係数は6色で同じ効果を持つようになった。

## Consequences

良い結果
- 6色が人間の目に同じ明るさで見える。どの色のタグも同じ程度に目立つ。
- 黄・緑・シアンが濃くなり、白い背景での視認性が上がる。
- ADR 002 の Dots の暗さの調整が、6色で同じように効く。

悪い結果
- 同じタグから生成されるアイコンと下線の色が変わる。既存の利用者が見た目の変化に気づく。
- 青だけ彩度が下がり、淡くなる。
- HSL の彩度と明度は色ごとにばらつく。HSL で見たときの統一感はなくなる。

中立的な結果
- `tests/golden.rs` の期待値を新しい色に更新した。下線の形は変わっていない。
- 色の調整は `cargo run --example swatches > swatches.html` で確認できる。
